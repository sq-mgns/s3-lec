# 5. Безопасность загрузки файлов

Это обязательный раздел. Если в проекте есть требования уровня NFR по безопасности файлов, этот раздел нужно изучить особенно внимательно.

Главный принцип:

> Любой пользовательский файл считается недоверенным.

---

## 5.1. Основные угрозы

### 1. Загрузка вредоносного исполняемого файла

Пример:

- `.exe`
- `.bat`
- `.sh`
- `.dll`
- `.jar`

Если система разрешает исполняемые файлы, злоумышленник может распространять вредоносное ПО.

---

### 2. Подмена типа файла

Пользователь может назвать файл:

```text
image.png
```

но вложить туда скрипт или архив.

---

### 3. XSS через загруженные файлы

Особенно актуально для:

- HTML;
- SVG;
- XML;
- некоторых текстовых форматов.

Если такой файл открывается в браузере как документ, он может выполнить скрипт в контексте домена.

---

### 4. Загрузка веб-шелла

Если приложение где-то сохраняет файлы в публичной директории и позволяет их исполнять или открывать, злоумышленник может получить удаленный доступ.

---

### 5. ZIP-бомбы и архивы с большим уровнем сжатия

Архив небольшого размера может распаковаться в огромный объем данных и привести к отказу в обслуживании.

---

### 6. Переполнение дискового пространства

Если не ограничивать размер файлов и квоты пользователей, хранилище можно быстро исчерпать.

---

### 7. Атаки на обработчики изображений

Если сервер масштабирует, конвертирует или парсит изображения, уязвимости в библиотеках обработки могут стать точкой компрометации.

---

## 5.2. Обязательные базовые проверки

### 1. Разрешайте только нужные типы файлов

Используйте allowlist, а не denylist.

Пример разрешенных расширений:

```text
.pdf
.png
.jpg
.jpeg
```

Не разрешайте:

```text
.html
.svg
.js
.exe
.bat
.sh
.php
```

если это не требуется явно и не защищено отдельно.

---

### 2. Проверяйте фактический тип файла

Не доверяйте:

- расширению;
- заголовку `Content-Type`;
- имени файла.

Проверяйте содержимое.

Для этого можно использовать:

- [python-magic](https://github.com/ahupp/python-magic)

Пример:

```python
import magic

mime_type = magic.from_file("uploaded_file", mime=True)

if mime_type not in ALLOWED_MIME_TYPES:
    raise ValueError("Недопустимый тип файла")
```

---

### 3. Генерируйте случайные имена файлов

Никогда не используйте пользовательское имя файла как имя в хранилище.

Плохо:

```python
key = f"uploads/{file.filename}"
```

Хорошо:

```python
key = f"uploads/{uuid4()}{extension}"
```

---

### 4. Ограничивайте размер файла

Например:

```python
MAX_FILE_SIZE = 10 * 1024 * 1024
```

И проверяйте размер во время чтения потока, а не после полной загрузки в память.

---

### 5. Храните файлы вне публичной веб-директории

В случае S3/MinIO это означает:

- бакет должен быть приватным;
- доступ только через приложение или подписанные ссылки;
- никаких публичных бакетов для пользовательских загрузок без необходимости.

---

### 6. Отдавайте файлы как вложения

Для пользовательских файлов лучше использовать:

```http
Content-Disposition: attachment
```

а не:

```http
Content-Disposition: inline
```

Это снижает риск исполнения или рендеринга опасного содержимого в браузере.

---

### 7. Используйте временные ссылки

Вместо постоянного прямого доступа:

```text
/files/document.pdf
```

лучше отдавать:

```text
/files/{id}/download
```

который генерирует короткоживущий signed URL.

---

### 8. Логируйте загрузки

Минимальный набор:

- кто загрузил;
- когда;
- размер;
- хеш;
- ключ объекта;
- результат проверки;
- причина отказа.

---

## 5.3. Дополнительные меры защиты

### Антивирусное сканирование

Для файлов, которые могут быть опасны, можно использовать антивирусную проверку.

Например:

- [ClamAV](https://docs.clamav.net/)

Сценарий:

1. Файл загружается во временное хранилище.
2. Проходит проверку.
3. Только после этого помечается как доступный.

---

### Изоляция обработки

Если файлы нужно парсить, конвертировать или извлекать из архивов:

- делайте это в изолированном процессе;
- ограничивайте время выполнения;
- ограничивайте память и CPU;
- не выполняйте это в основном веб-процессе.

---

### Защита от ZIP-бомб

Если принимаете архивы:

- проверяйте распакованный размер;
- ограничивайте количество файлов;
- ограничивайте глубину вложенности;
- не распаковывайте автоматически все подряд.

---

### Проверка изображений

Если принимаете изображения:

- используйте надежные библиотеки;
- обновляйте зависимости;
- проверяйте реальный формат;
- не исполняйте изображения;
- при необходимости пересжимайте/перекодируйте файлы.

---

## 5.4. Чек-лист безопасности загрузки файлов

Перед релизом проверьте:

- [ ] Разрешены только допустимые расширения.
- [ ] Проверяется фактический MIME-тип файла.
- [ ] Ограничен максимальный размер файла.
- [ ] Имя файла в хранилище генерируется сервером.
- [ ] Файлы не хранятся в публичной директории.
- [ ] Бакет приватный.
- [ ] Пользователи получают файл только через авторизованный эндпоинт.
- [ ] Используются короткоживущие подписанные ссылки.
- [ ] Файлы отдаются как `attachment`, если нет явной причины для `inline`.
- [ ] Логируются факты загрузки и отказа.
- [ ] Реализована защита от повторных злоупотреблений.
- [ ] Есть лимиты на количество загрузок.
- [ ] Для потенциально опасных типов включено сканирование.
- [ ] Ошибки загрузки не раскрывают лишнюю внутреннюю информацию.

# Итог

Безопасность при работе с пользовательскими файлами — это не дополнительная опция, а базовая часть архитектуры. Главные меры — allowlist типов, ограничение размера, случайные имена, приватный бакет и временные ссылки, а также проверка фактического содержимого файла.
