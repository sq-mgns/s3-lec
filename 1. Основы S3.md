# 1. Основы S3

## 1.1. Что такое S3

Amazon S3 — это объектное хранилище. В отличие от классической файловой системы, где файлы лежат в каталогах, а доступ к ним происходит через пути вида `/var/app/uploads/file.pdf`, S3 оперирует плоским пространством объектов.

Объект в S3 — это не просто файл. Он состоит из:

- самого содержимого — байтов файла;
- ключа — имени объекта внутри бакета;
- метаданных — служебных и пользовательских данных;
- версии — если включено версионирование;
- дополнительной информации, например `ETag`, storage class, дата последней модификации.

Важно: S3 не является обычной файловой системой. Его нельзя просто примонтировать как диск и ожидать поведение локальной ФС без оговорок.

Полезные материалы:

- [Amazon S3 User Guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html)
- [Amazon S3 objects overview](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingObjects.html)
- [Working with Amazon S3 buckets](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingBucket.html)

## 1.2. Bucket — бакет

Бакет — это контейнер для объектов.

Основные свойства бакета:

- имя бакета уникально в рамках AWS-аккаунта, а для S3 в AWS — глобально;
- бакет находится в определенном регионе;
- в AWS количество бакетов на аккаунт ограничено, но лимит можно увеличивать;
- внутри бакета хранятся объекты;
- для бакета настраиваются политики доступа, CORS, versioning, lifecycle rules, encryption и другие параметры.

Пример имени бакета:

```text
myapp-user-uploads-prod
```

В локальном MinIO имя бакета тоже должно быть уникальным в рамках одного MinIO-инстанса.

---

## 1.3. Object — объект

Объект — это единица хранения в S3.

Пример объекта:

```text
Bucket: myapp-user-uploads-prod
Key:    users/42/documents/report.pdf
Size:   2.4 MB
Type:   application/pdf
```

Важно понимать, что объект идентифицируется парой:

```text
bucket + key
```

То есть один и тот же ключ может существовать в разных бакетах, но внутри одного бакета ключ уникален.

---

## 1.4. Key — ключ объекта

Ключ — это имя объекта внутри бакета.

Примеры ключей:

```text
avatar.png
users/42/avatar.png
documents/2026/02/report.pdf
tmp/import/2026-02-22/file.csv
```

Хотя ключи часто выглядят как пути к файлам, в S3 нет настоящих папок.

Когда вы видите:

```text
users/42/avatar.png
```

S3 воспринимает это как одну строку-ключ. Слэш `/` здесь — просто символ, который удобно использовать как логический разделитель.

То есть структура:

```text
users/
  42/
    avatar.png
```

визуально отображается в консоли как папки, но физически это один объект с ключом `users/42/avatar.png`.

Практический вывод:

- не стоит воспринимать S3 как обычную файловую систему;
- для организации объектов лучше использовать префиксы;
- ключ можно генерировать программно, например:

```text
uploads/2026/02/22/9f2f7f7a-3d1a-4e46-9a1e-3f9d0c1f2f3a.pdf
```

## 1.5. Метаданные объекта

У каждого объекта есть метаданные.

Они делятся на:

1. Системные.
   Например:
   - `Content-Type`
   - `Content-Length`
   - `Last-Modified`
   - `ETag`

2. Пользовательские.
   Например:
   - `x-amz-meta-original-name: report.pdf`
   - `x-amz-meta-uploaded-by: 42`
   - `x-amz-meta-sha256: 8f3a...`

Пользовательские метаданные полезны, но у них есть ограничения:

- они хранятся как строки;
- не все символы безопасно передавать в заголовках;
- для сложных данных лучше использовать базу данных приложения, а в объектном хранилище хранить только ссылку/ключ и минимально необходимые атрибуты.

---

## 1.6. Основные операции

Типовые операции с объектами:

- загрузить объект;
- скачать объект;
- удалить объект;
- получить список объектов;
- получить метаданные объекта;
- скопировать объект;
- сгенерировать временную ссылку на доступ.

В S3 доступ обычно выполняется по HTTP-модели:

- `PUT` — загрузка;
- `GET` — скачивание;
- `DELETE` — удаление;
- `HEAD` — получение метаданных.

---

## 1.7. Ограничения и важные особенности

Что нужно знать заранее:

1. Максимальный размер объекта в S3 — до 5 ТБ.
2. Одним обычным `PUT`-запросом нельзя загрузить очень большие файлы, для больших файлов используется multipart upload.
3. Ключ объекта может быть длинным, но это строка, а не путь в ФС.
4. В одном бакете может быть огромное количество объектов.
5. Для приватных бакетов нельзя просто отдавать файлы по прямой ссылке без настройки доступа.
6. Для выдачи файла пользователю лучше использовать временные подписанные ссылки.
7. Если файл загружает пользователь, файл нужно считать недоверенным.

# Итог

S3 — это объектное хранилище, а не файловая система. Для разработки важно понимать модель бакетов, объектов и ключей, чтобы хранить пользовательские файлы безопасно и предсказуемо.
